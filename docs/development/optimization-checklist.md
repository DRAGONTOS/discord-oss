# Optimization checklist

Candidate work found in a source review on 2026-11-20. Items here are investigations, not confirmed bottlenecks. Items already marked done in [work-backlog.md](work-backlog.md) are left out. Measure before and after any change, and keep benchmark claims tied to fixture size, host and revision.

## Quick wins

- [x] **OPT-001** Use a Set for guild membership in identify. `src/gateway/opcodes/Identify.ts:750` calls `memberGuildIds.includes(id)` inside a filter over client guild versions, which is O(guilds squared) per identify. Risk: none.
- [x] **OPT-002** Bound the member typeahead query. `src/api/routes/guilds/#guild_id/members/search.ts:40-61` loads every matching member and one row per role before slicing in JavaScript. Add `.take(limit)`, project only the needed columns and attach roles to the returned page. Risk: low.
- [x] **OPT-003** Bound the reaction-user query. `src/api/routes/channels/#channel_id/messages/#message_id/reactions.ts:168-179` loads the whole message and puts every reactor id in an `In` clause for a page of 25. Select only `reactions`, page the ids first and query with just those ids. Risk: low; cover `after` and both reaction types in a test.
- [x] **OPT-004** Cap the E2EE retry delay. `client/e2ee/src/index.ts:301` uses the server's `retry_after` with no upper limit for a 429, while the other branch caps at 300000 ms. Clamp it and show a clear try again later state. This caused a startup stall during local testing. Risk: low.
- [x] **OPT-005** Run search tabs concurrently. `src/api/util/utility/MessageSearch.ts:200-207` runs up to 10 independent searches serially. Use a worker cap of 2 or 3. Risk: low; watch database concurrency.
- [ ] **OPT-006** Cache the Equicord source in Docker builds. Skipped by owner, who wants full image rebuilds. `Dockerfile:34` clones, patches and builds Equicord and deletes `/tmp/vencord` in the same layer, so every rebuild repeats the clone and toolchain install. Use a BuildKit cache mount or a persistent stage. Risk: low.

## REST and database

- [ ] **OPT-010** Push guild member search into SQL. Partial: member hydration reduced and roles batched in `617e27c` follow-up, but the filters still run in JavaScript. Full SQL pushdown remains. `src/api/routes/guilds/#guild_id/members-search.ts:53-125` loads the entire guild with users and roles, then filters and sorts in JavaScript. Use SQL predicates, keyset pagination and a capped count, as message search does. This is the main blocker behind PERF-021. Risk: medium, needs parity tests for the filter and sort modes.
- [x] **OPT-011** Index the crosspost source id. `src/api/util/handlers/Message.ts:781-816` scans all messages through `message_reference ->> 'message_id'` on every cross-post edit. Add an expression index on PostgreSQL and the SQLite equivalent, or use the existing indexed `message_reference_id` column. Drop the unused webhook relation. Risk: low to medium.
- [x] **OPT-012** Batch role assignment. `src/api/routes/guilds/#guild_id/roles/#role_id/members.ts:21-30` calls `Member.addRole` once per member, up to 30 times, for roughly 120 queries. Use one batched insert and emit the events in parallel, preserving the single authorization check. Risk: medium.
- [x] **OPT-013** Batch bulk read state acknowledgements. `src/api/routes/read-states/ack-bulk.ts:25-53` does a find and a save per entry for up to 100 entries. Use one upsert with `GREATEST` for last message id, then emit events. Risk: low.
- [x] **OPT-014** Parallelize crosspost followers. `src/api/routes/channels/#channel_id/messages/#message_id/crosspost.ts:50-78` awaits one follower at a time. Prepare copies in parallel with shared channel and permission data, keeping the per-follower error isolation. Risk: medium.
- [x] **OPT-015** Replace the channel ordering N+1. `src/database/entities/Channel.ts:604-624` issues one query per channel and uses `indexOf` in a loop. One `In` query and a position map are enough. Only caller is the widget route, so impact is low. Risk: low.
- [x] **OPT-016** Batch thread mention permission checks. `src/api/util/handlers/Thread.ts:209-217` calls `getPermission` per mentioned member at about four queries each. Compute permissions in one batch and insert thread members together. Risk: medium.
- [ ] **OPT-017** Batch preload message permissions. Deferred: `getPermission` has thread, lurker and MFA branches that a batch rewrite could change; needs dedicated parity tests. The current calls already run in parallel. `src/api/routes/channels/preload-messages.ts:31-52` calls `getPermission` once per requested channel. Load members and roles once and evaluate overwrites in memory. Risk: medium.
- [x] **OPT-018** Bound periodic sweep work per tick. `src/api/util/handlers/ImageFiles.ts:60-63`, `AttachmentFiles.ts:17-20` and `MessagePurge.ts:19-36` call sweep functions with an infinite deadline from their timers. Pass a short deadline so a tick does bounded work. Risk: low.
- [x] **OPT-019** Check the role member count query. `src/api/routes/guilds/#guild_id/roles/member-counts.ts:11-19` uses `COUNT(DISTINCT m.id)` over a join. Check existing indexes before adding a covering index. Impact is low. Risk: low.

## Gateway, voice and SFU

- [x] **OPT-020** Cache the full dispatch envelope per event. `src/gateway/util/Send.ts:10-48` caches only the JSON of `d`, then rebuilds the wrapper, recomputes byte length and reparses for ETF once per socket. Cache the wrapper pieces, byte count and parsed object. Risk: low to medium; audit emitters that mutate event data.
- [x] **OPT-021** Index SFU tracks by SSRC. `extra/pion-sfu/native.go:543-558` calls `PeerSnapshot` per native RTCP packet, allocating a slice of all peers and locking each publisher. Add an SSRC to track index and maintain it on publish, replace and leave. Risk: medium; extend the race tests.
- [x] **OPT-022** Reduce per-packet SFU allocations. `extra/pion-sfu/multiplextrack.go:93-154` allocates an extension slice per binding and packet, and `native.go:69-147` allocates a nonce, header, suffix and packet per packet. Add benchmarks first, then use scratch buffers and pools. Risk: medium.
- [x] **OPT-023** Cancel replaced track readers. `extra/pion-sfu/main.go:392-437` closes a stop channel but the reader blocks in `ReadRTP`, leaking a goroutine and receiver per track switch. `extra/pion-sfu/recovery.go:231-253` has no stop check. This closes JOB-007. Risk: low to medium.
- [x] **OPT-024** Index voice clients. `src/webrtc/pion/PionMediaServer.ts:222-230` and `:264-272` scan all rooms and clients on connect and join. Maintain maps by unique id and user id. Risk: low.
- [x] **OPT-025** Bound IPC requests. `src/webrtc/pion/IpcClient.ts:34-41` and `:117-131` keep an unbounded pending map with one timer per request. Add an in-flight cap and batch subscribe messages. Risk: moderate.
- [x] **OPT-026** Batch NACK retransmission locks. `extra/pion-sfu/recovery.go:359-386` takes a sequence lock and a packet cache lock per retransmitted packet. Allocate a sequence range per NACK batch and hold one cache lock. Risk: medium.
- [x] **OPT-027** Check H.264 and RTX negotiation. Done: MIME matching is case-insensitive, `apt` is parsed numerically, the server parses the client SDP fmtp with an allowlist (42e01f/4d0028/64001f/640028) and 42e01f fallback, and the SFU registers all four profiles. Cross-client voice verification is still pending. `extra/pion-sfu/multiplextrack.go:50-58` and `:69-73` match MIME and `apt` with exact strings, and `src/webrtc/pion/PionMediaServer.ts:293-331` hardcodes a profile level. This closes APP-024. Risk: medium, needs cross-client tests.
- [x] **OPT-028** Avoid a string allocation per native packet. `extra/pion-sfu/native.go:348` calls `addr.String()` for a map lookup. Key by `netip.AddrPort`. Risk: low.
- [x] **OPT-029** Reduce IPC frame buffer copies. `src/webrtc/pion/IpcClient.ts:87-96` calls `Buffer.concat` per data chunk. Accumulate chunks and concat once per frame. Impact is low because this is signaling only. Risk: low.
- [x] **OPT-030** Use the reverse subscription index when a peer leaves. `extra/pion-sfu/main.go:463-465` snapshots all peers and drops sinks by scanning. Risk: low.
- [x] **OPT-031** Replace the transaction dedup array scan. `src/gateway/listener/listener.ts:462-466` uses `includes` and `slice(1)` per event with a transaction id. Use a ring buffer of sets. Risk: low.
- [ ] **OPT-032** Skip the guild cache freshness query when cached. Skipped: `GuildCacheEventId` is not emitted for MESSAGE_CREATE/DELETE, which mutate `last_message_id` and `version`, so skipping the query would serve stale values for up to 5 minutes. `src/gateway/util/GuildCache.ts:84-99` queries all channel rows on every identify despite event driven invalidation. Risk: medium, stale version risk if invalidation events are missed.
- [ ] **OPT-033** Treat the fanout presence gap as a baseline. Investigated, no code change: the probe resolves on READY before the async member-list subscription is established, so a subset of sockets can legitimately miss a presence update. The ~17/50 gap is a probe artifact, not a fanout bug. `docs/development/work-backlog.md` PERF-024 records that about 17 of 50 sockets with a member list miss each presence update. Investigate before claiming further fanout wins. `scripts/dev/gateway-fanout.mjs:312-322` has the probe.

## Client and E2EE

- [x] **OPT-040** Bound the E2EE state map and scope DOM decoration. `client/e2ee/src/index.ts:32` grows `states` per decrypted message, and `ui.ts:1265-1410` sweeps all states on each refresh from a global MutationObserver. Bound the map and decorate only changed message ids. Risk: medium, needs an E2EE run.
- [x] **OPT-041** Cache imported Ed25519 keys. `client/e2ee/src/crypto.ts:22-32` calls `importKey` on every verify across message receive and key lookup. Memoize by encoded key with a bounded map. Risk: low.
- [x] **OPT-042** Memoize safety numbers. `client/e2ee/src/engine.ts:1462-1479` performs about 10400 sequential SHA-512 digests per member, called per member in `ui.ts:504`. Cache by key pair and coalesce concurrent calls. Risk: low.
- [x] **OPT-043** Refresh only stale key directory entries. `client/e2ee/src/engine.ts:1108-1110` refetches and re-verifies every user when one entry expires. Partition stale and fresh ids. Risk: low to medium.
- [x] **OPT-044** Short circuit local URL rewriting. `assets/client_patches/70-local-cdn.js:58-107` wraps DOM attribute and property setters and runs URL parsing plus regexes on every write. Skip work when the value has no URL host and memoize rewritten values. Risk: medium, needs `check:client` and a render smoke.
- [x] **OPT-045** Scope the safety CTA observer. `client/plugins/fosscordSafetyCTAs/index.ts:31-34` runs a subtree MutationObserver and a query per added node. Debounce to one frame, pre-filter node tag names. Risk: low.
- [x] **OPT-046** Gate music presence timers. `client/plugins/fosscordMusicPresence/index.tsx:257-258` runs two 15 second intervals with no connected accounts. Create them only when an account exists. Risk: low.
- [x] **OPT-047** Keep a running service worker file byte total. `client/e2ee/src/sw.ts:85-90` reduces over all files on each insert. Risk: low.
- [x] **OPT-048** Cache the toolbar node. `client/e2ee/src/ui.ts:1287` queries the whole document per refresh. Reuse a reference per channel. Risk: low.

## Verification rules

Run probes and benchmarks only on an instance and database created for the test. Never clear rate limits or reset accounts on a shared database. Build before running `bun test`, and treat the environment failures listed in CONTRIBUTING.MD as the baseline. Run `check:client` after any client patch or plugin change, `e2ee-test.mjs` after E2EE changes, and `voice-probe.mjs` after SFU or voice changes.
